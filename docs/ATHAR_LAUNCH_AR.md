# تجهيز وربط تطبيق أثر

التطبيق الأصلي محفوظ مع الخادم في `ios/AtharQuest`. هذه النسخة تضيف ربطًا فعليًا بمنصة نقاط الأثر، ولا تغيّر تطبيق TestFlight المنشور بمجرد دمج الكود. يلزم نشر الخادم ثم رفع بناء iOS جديد.

## مكان الإدارة

بعد النشر: سجّل الدخول بحساب إدارة المنصة ثم افتح **إدارة تطبيق أثر** من القائمة، أو `/admin/athar`.

- **الإعدادات:** تشغيل التطبيق أو وضع التجهيز، تشغيل الأقسام، روابط الدعم والخصوصية والشروط والمشاركة العامة، هدف الأثر الجماعي، وحد طلبات الصناديق.
- **المتجر:** منتجات منصة نقاط الأثر نفسها؛ الاسم والوصف والفئة والتكلفة والمخزون والحالة وعنوان التوصيل. المخزون هو الإجمالي بما فيه المحجوز والمسلّم؛ المتاح = الإجمالي ناقص الطلبات غير المرفوضة.
- **الطلبات:** مراجعة طلبات الويب والآيفون في مكان واحد. `pending → approved → paid` أو الرفض من pending/approved. الرفض يعيد الرصيد والمخزون؛ الطلب المسلّم أو المرفوض لا يعاد فتحه.
- **المسابقات:** مسودة تشمل الأسئلة والأجوبة والشروح والمراجع واعتماد المحتوى. بعد الجدولة تقفل الشروط. عند الموعد يبدأ المشرف الجولة، ويمكن إيقافها مؤقتًا واستئنافها أو إلغاؤها. بعد نهاية الأسئلة يعاين النتائج ثم ينشرها. تبقى النتائج المنشورة متاحة للاستلام.
- **المهام:** نوع المهمة والهدف وفترتها ومكافأتها. المشاركة والتدريب يمنحان نقاط تدريب فقط. مهام الأثر تعتمد على البيانات المتزامنة وطلبات الصناديق المعتمدة. كل مهمة تُستلم مرة واحدة؛ للتكرار الأسبوعي أنشئ مهمة جديدة. مهمة مبالغ الأثر تقيس إجمالي التبرعات المعتمدة للصناديق التي أُنشئت خلال الفترة، وليست كشف تبرعات حسب تاريخ الدفع.
- **الصناديق:** طلب إنشاء للمراجعة. أنشئ الصندوق بحساب السفير في منصة التبرع بالطريقة الحالية ثم شغّل مزامنة المنصة وأدخل رقمه لاعتماده. الخادم يتحقق أن الصندوق المتزامن يخص السفير قبل نشر الرابط. لا توجد عملية إنشاء آلية جديدة في ديسق ضمن هذا التغيير.
- **سجل الإدارة:** إعدادات وتغييرات المنتجات والمسابقة والطلبات والصناديق، مع تصدير CSV.

## الحسابات والأرصدة

الدخول برقم الجوال وكلمة المرور الموجودين في المنصة. يُحفظ رمز جلسة عشوائي في Keychain، وتُحفظ بصمته فقط في MongoDB. ينتهي بعد سبعة أيام ويُلغى عند الخروج أو تغيير كلمة المرور. التسجيل واستعادة كلمة المرور من صفحة المنصة الحالية.

الرصيد موحّد: مجموع `AllFund.currentTotal` الخاص بالسفير + `BonusPoints` − طلبات `PrizeRequest` المعلّقة والمعتمدة والمسلّمة، مع تقريب الرصيد المتاح للأسفل إلى عدد صحيح. مكافأة المسابقة أو المهمة تُكتب مرة واحدة في BonusPoints. لا تُضاف نقاط متجر على الجهاز. تستمر مزامنة التبرعات الموجودة في المنصة؛ هذه الإضافة لا تنشئ مصدرًا بديلًا لبيانات الدفع.

الاستبدال يستخدم transaction مع قفل كتابة للسفير والمنتج. مسار الويب القديم يمر بالخدمة نفسها لمنع إنفاق الرصيد نفسه من الويب والآيفون. يحافظ التطبيق على Idempotency-Key عند فشل الشبكة أو الخادم، حتى بعد إعادة تشغيل التطبيق. المرجع الفريد يحمي استلام المسابقة والمهمة أيضًا.

## تجهيز الخادم

1. احتفظ بنسخة احتياطية من قاعدة البيانات والمستودع قبل النشر.
2. استخدم Node.js 20.19 أو أحدث وMongoDB 7 أو إصدار متوافق يدعم transactions عبر **Replica Set أو Atlas**. لا تنشر تعديل الاستبدال على MongoDB standalone؛ ستفشل عمليات الطلب بدل تنفيذ خصومات غير ذرّية. تحويل قاعدة قائمة إلى replica set إجراء تشغيل منفصل يُختبر على نسخة أولًا.
3. أبقِ متغيرات المنصة الحالية `MONGO_URI` و`SESSION_SECRET` وتكامل التبرعات الحالية على الخادم. لا يلزم مفتاح API إداري داخل تطبيق iOS.
4. ثبّت باستخدام `npm ci` ثم شغّل `node scripts/atharReadiness.js --prepare-indexes`. هذا ينشئ الفهارس المطلوبة دون حذف الفهارس الموجودة. يعرض PENDING للإعدادات التي لم تُفعّل بعد؛ قبل التفعيل فهذا متوقع. أي تعارض فهرس يحتاج تصحيح البيانات قبل الإطلاق.
5. انشر الخادم وراء HTTPS، وتأكد أن `/v1/config` يعيد JSON وأن `/v1/ambassador/dashboard` يعيد 401 دون توكن. لا تخزّن `/v1/*` أو `/admin/athar/*` في CDN.
6. اضبط الإعدادات والمحتوى من الإدارة، وأدخل روابط الخصوصية والشروط المعتمدة، ثم فعّل التطبيق والأقسام المطلوبة. لا تُزرع أسئلة إنتاجية أو منتجات أو مكافآت تلقائيًا.
7. أعد `node scripts/atharReadiness.js`، وجرّب حسابين واستبدالًا ومسابقة قصيرة في بيئة تجريبية قبل التشغيل العام.

## بناء الآيفون

افتح `ios/AtharQuest/AtharQuest.xcodeproj`. إعدادا البناء:

- `ATHAR_API_BASE_URL`: افتراضيًا `https://sfeer.site` كما هو دومين المنصة المستخدم في المستودع؛ عدّله إذا كان نطاق النشر مختلفًا.
- `ATHAR_API_MODE`: `live`. يسمح Debug وحده باختيار `demo` للاختبار. Release يفرض الربط الحي، ولا يعود تلقائيًا إلى بيانات وهمية عند نقص الإعدادات.

معرف التطبيق الحالي `com.zeyadalsaloum.atharquest` محفوظ. قبل الرفع اختر Team والتوقيع الموجودين وارفع رقم Build فوق آخر رقم في App Store Connect. لم نتحقق من رقم TestFlight الحالي ولم تُنشأ أو تُلغَ أي شهادة. بناء Release اختُبر بدون توقيع؛ ذلك لا يعني رفع نسخة جديدة إلى TestFlight.

الأسماء والمخزون والمواعيد في الوضع الحي تأتي من الخادم. أسئلة النموذج التجريبية مستبعدة من Release. عند تعطل الاتصال تُوقف الإجابات حتى المزامنة؛ لا تُقبل إجابات مخزنة محليًا خارج نافذة السؤال.

## بروتوكول المسابقة المنفذ

التزامن بلقطات HTTP كل ثانية عندما تكون الشاشة نشطة، مع العودة للمزامنة عند فتح التطبيق أو انقطاع الاتصال. لا يعتمد التنفيذ الحالي على WebSocket. المصدر الوحيد للتوقيت والدرجات هو الخادم.

- `GET /v1/config`
- `POST /v1/auth/login`، `POST /v1/auth/logout`
- `GET /v1/ambassador/dashboard`
- `POST /v1/ambassador/boxes`، `POST /v1/ambassador/events/share`
- `POST /v1/ambassador/missions/claim`، `POST /v1/ambassador/game/completions`
- `POST /v1/ambassador/store/redemptions` مع `productID` و`shippingAddress` و`Idempotency-Key`
- `GET /v1/ambassador/store/orders`
- `GET /v1/competitions/upcoming`
- `POST /v1/competitions/:id/join`
- `GET /v1/competitions/:id/snapshot`
- `POST /v1/competitions/:id/questions/:questionID/answers` مع `choiceID` من 0 إلى 3
- `POST /v1/competitions/:id/rewards/claim`

اللقطة لا تتضمن إجابة صحيحة أو نقاط السؤال حتى إغلاقه، والترتيب يستبعد السؤال المفتوح. تُحتسب أول إجابة فقط باستخدام وقت وصولها للخادم. الانضمام متاح خلال الانتظار والسؤال الأول. الأهلية = نسبة الأسئلة المجاب عنها + درجة صحيحة أكبر من صفر. التوزيع بأكبر البواقي يحافظ على مجموع الحوض إذا وُجد مؤهلون؛ إذا لم يتأهل أحد فلا توزّع نقاط. عند تعادل الدرجات يكون الترتيب بمعرّف السفير الثابت. لا يمكن استلام مكافأة قبل نشر النتائج.

لا يوجد حاليًا إلغاء سؤال فردي أو جدولة بدء آلية؛ التحكم يبدأ ويوقف الجولة كاملة من الإدارة. يلزم اختبار حمل وتقييم هامش الشبكة قبل مسابقة كبيرة؛ الاختبارات الحالية وظيفية وتزامن محدود.

## التحقق المحلي

```sh
npm ci
npm test
scripts/testAtharIOS.sh
xcodebuild -project ios/AtharQuest/AtharQuest.xcodeproj -scheme AtharQuest \
  -sdk iphonesimulator -configuration Debug -derivedDataPath /tmp/athar-derived \
  CODE_SIGNING_ALLOWED=NO ARCHS=arm64 build
xcodebuild -project ios/AtharQuest/AtharQuest.xcodeproj -scheme AtharQuest \
  -sdk iphoneos -configuration Release -derivedDataPath /tmp/athar-release \
  CODE_SIGNING_ALLOWED=NO build
```

تعمل اختبارات الخادم على MongoDB Replica Set مؤقت مستقل، ولا تقرأ `.env` أو بيانات الإنتاج. تُنشئ ملفات عقد في `output/contracts` تستخدمها اختبارات Swift للتحقق من فك الترميز ومعرّفات إعادة المحاولة.

لمعاينة الإدارة: `node scripts/previewAthar.js` ثم `http://127.0.0.1:4317/admin/athar`. هذه عملية محلية معزولة ببيانات تجريبية وجلسة إدارة تلقائية؛ لا تُستخدم للنشر وتُرفض عند NODE_ENV=production. الدخول التلقائي ليس موجودًا في server.js.

## حالة التسليم

الكود واختبارات الخادم وSwift وتجهيز لوحة الإدارة مكتملة في فرع التطوير. النشر الفعلي، التحقق من إعداد MongoDB في الإنتاج، إدخال المحتوى والروابط المعتمدة، تجربة التكامل مع بيانات الإنتاج، وتوقيع ورفع TestFlight مراحل إطلاق لم تُنفذ ضمن تجهيز الكود.
