# عقد API المقترح لتطبيق أثر

جميع المسارات تبدأ من `ATHAR_API_BASE_URL`، وتستخدم JSON وHTTPS. يرسل التطبيق:

```http
Authorization: Bearer <access-token>
Accept-Language: ar-SA
Content-Type: application/json
```

التواريخ بصيغة ISO 8601، والمبالغ أرقام عشرية بالريال. يجب أن يحدد الخادم الجهة والسفير من التوكن، ولا يقبل `ambassador_id` مرسلًا من التطبيق كمرجع صلاحية.

## 1. لوحة السفير

`GET /v1/ambassador/dashboard`

يعيد كائنًا مطابقًا لـ `DashboardPayload`:

- `profile`: الاسم، مستوى التدريب، نقاط التدريب، ورصيد المتجر.
- `impact`: مبالغ منسوبة ومتحققة، عدد المتبرعين، المشاركات، والصناديق النشطة.
- `missions`: المهمات الحالية وحالاتها.
- `boxes`: صناديق السفير المصرح بها.
- `products`: المنتجات والمخزون.
- `gameProgress`: مراحل لعبة التدريب ونتائجها.
- `generalShareURL`: رابط عام موقّع أو منسوب للسفير.

## 2. إنشاء صندوق تذكاري

`POST /v1/ambassador/boxes`

```json
{
  "deceasedName": "محمد بن عبدالله",
  "title": "صدقة جارية عن محمد بن عبدالله",
  "target": 5000
}
```

يفضّل أن يعيد الخادم حالة `pending_review` أولًا. لا ينشر التطبيق رابطًا عامًا حتى تصبح الحالة `active`. يجب تطبيق تنقية النص، حد الإنشاء، ومنع التكرار في الخادم.

## 3. تسجيل مشاركة

`POST /v1/ambassador/events/share`

```json
{
  "resourceID": "box-123-or-null-for-general-link",
  "destination": "com.apple.UIKit.activity.Message"
}
```

هذا الحدث تحليلي، وليس دليلًا على وصول تبرع. يجوز أن يمنح نقاط تدريب بحد يومي، لكنه لا يمنح رصيد متجر عينيًا. الإسناد الحقيقي يعتمد على توكن الرابط وحدث الدفع المؤكد.

## 4. استلام مهمة

`POST /v1/ambassador/missions/claim`

```json
{ "missionID": "weekly-impact" }
```

يجب أن يكون الاستلام idempotent؛ إرسال الطلب مرتين يعيد الإيصال نفسه ولا يكرر النقاط. يستحسن في النسخة الإنتاجية أن يعيد الخادم المهمة والرصيدين الجديدين معًا.

## 5. نتيجة اللعبة

`POST /v1/ambassador/game/completions`

```json
{
  "level": 4,
  "stars": 3,
  "elapsedSeconds": 52,
  "playStyle": "challenge"
}
```

لا يمنح هذا المسار رصيد متجر. يتحقق الخادم من حدود منطقية للمرحلة ويقبل أفضل نتيجة فقط. يرسل التطبيق مفتاح idempotency في النسخة الإنتاجية عند دعم اللعب دون اتصال.

## 6. استبدال منتج

`POST /v1/ambassador/store/redemptions`

```json
{ "productID": "thermal-mug" }
```

العملية كلها داخل transaction واحدة:

1. قفل رصيد السفير وصف المخزون.
2. التحقق من كفاية الرصيد والمخزون وحالة السفير.
3. خصم النقاط والمخزون.
4. إنشاء طلب وإرجاع الإيصال.

الرد المتوقع:

```json
{
  "id": "RDM-48291",
  "productID": "thermal-mug",
  "productName": "كوب أثر الحراري",
  "pointsSpent": 450,
  "remainingPoints": 830,
  "statusText": "بانتظار تأكيد العنوان"
}
```

## 7. المسابقة المباشرة

المسابقة ليست طلب HTTP عاديًا فقط؛ تحتاج قناة بث، ساعة خادم، وإخفاء الإجابة الصحيحة حتى إغلاق السؤال. العقد الكامل موجود في [LIVE_COMPETITION_API_AR.md](LIVE_COMPETITION_API_AR.md).

لا يجوز للإصدار الحي إضافة مكافأة المسابقة إلى الرصيد محليًا. ينشر الخادم النتائج أولًا، ثم يعيد مسار الاستلام قيد ledger والرصيد النهائي بطريقة idempotent.

## قواعد الإسناد والاحتيال

- الرابط العام والصندوق يحملان توكنًا قصير العمر أو معرّف إسناد غير قابل للتخمين.
- التبرع يُنسب بعد نجاح الدفع من webhook موثوق، لا من صفحة نجاح على جهاز المتبرع.
- نقطة الاستبدال تُسجل في ledger غير قابل للتعديل المباشر: سبب، مرجع، قيمة، تاريخ، ومعاملة عكسية عند الاسترجاع.
- لا يسمح التطبيق باستهداف متبرعين جدد بفرصة خاصة، ولا بمشاركة فرصة مكتملة.
- Rate limit على إنشاء الصناديق، المشاركات المسجلة، والاستبدال.
- سجلات تدقيق لكل تغيير في الرصيد والمخزون وحالة الصندوق.

## حالات الخطأ

استخدم أكواد HTTP الصحيحة مع رسالة عربية آمنة:

- `401`: الجلسة منتهية.
- `403`: السفير موقوف أو لا يملك الإجراء.
- `409`: المهمة مستلمة، الصندوق مكرر، المنتج نفد، أو تغيّر الرصيد.
- `422`: حقول غير صالحة.
- `429`: تجاوز الحد.

يجب ألا تتضمن رسائل الخطأ بيانات داخلية أو استعلامات قاعدة البيانات.
