# عقد المسابقة القرآنية المباشرة

هذا العقد هو الحد الأدنى لتحويل المحاكاة الموجودة في التطبيق إلى مسابقة حية عادلة. الخادم هو المصدر الوحيد للوقت، الإجابات، الدرجات، الترتيب، وأرصدة المتجر.

## حالات المسابقة

`draft → scheduled → lobby → live → calculating → published → archived`

يمكن للمشرف إيقافها مؤقتًا أو إلغاؤها. لا يُسمح للهاتف بتغيير الحالة.

## HTTP

### المسابقات القادمة

`GET /v1/competitions/upcoming`

يعيد المعرّف والعنوان والموعد والمنطقة الزمنية وعدد الأسئلة ومدة كل سؤال وقيمة الحوض وشروط الأهلية. لا يعيد بنك الأسئلة كاملًا.

### الانضمام

`POST /v1/competitions/{id}/join`

```json
{
  "clientSessionID": "uuid",
  "appVersion": "2.0",
  "deviceTime": "2026-07-17T17:29:58Z"
}
```

يعيد تذكرة جلسة قصيرة العمر، وقت الخادم، ورابط اتصال البث. الطلب idempotent للسفير نفسه.

### إرسال الإجابة

`POST /v1/competitions/{id}/questions/{questionID}/answers`

```json
{
  "choiceID": 2,
  "answerID": "uuid",
  "shownSequence": 7,
  "clientElapsedMilliseconds": 3840
}
```

يسجل الخادم أول إجابة فقط. يعتمد التقييم على نافذة السؤال في الخادم، ويستخدم زمن العميل فقط كإشارة تدقيق لا كحقيقة. الرد لا يكشف الصحة قبل إغلاق السؤال.

### النتائج والاستلام

- `GET /v1/competitions/{id}/results/me`
- `POST /v1/competitions/{id}/rewards/claim`

الاستلام idempotent ويعيد إيصال ledger والرصيد الجديد. لا يضيف التطبيق النقاط محليًا في وضع الإنتاج.

### جولة الأثر

`POST /v1/competitions/{id}/impact-actions`

```json
{
  "actionID": "uuid",
  "type": "general_share",
  "resourceID": null
}
```

أنواعها: `general_share` و`box_share` و`box_create`. تسجيلها لا يثبت تبرعًا؛ أي نقاط مرتبطة بزيارة أو تبرع تُمنح لاحقًا من حدث موثوق.

## قناة البث

يمكن استخدام WebSocket أو خدمة بث موثوقة. الرسائل مرتبة بحقل `sequence`، وعلى التطبيق طلب لقطة مزامنة عند فقد رقم.

### رسائل الخادم الأساسية

- `lobby_snapshot`: عدد الحاضرين والوقت المتبقي.
- `question_opened`: نص السؤال، أربعة خيارات، `openedAt` و`closesAt`. لا يحتوي الإجابة الصحيحة.
- `answer_progress`: عدد من أجابوا فقط.
- `question_closed`: الإجابة الصحيحة والشرح والمرجع ودرجة السفير.
- `leaderboard_snapshot`: أعلى المراكز ومركز السفير والحركة منذ السؤال السابق.
- `competition_finished`: بدء حساب التوزيع.
- `results_published`: النتائج والحوض الموزع وإيصال قابل للاستلام.
- `competition_paused|cancelled`: سبب آمن للمستخدم وتعليمات الاستئناف.

## الدرجة الموثوقة

النموذج الحالي:

```text
إذا كانت خاطئة: 0
إذا كانت صحيحة:
500 + round(500 × remaining_ms / duration_ms)
```

يحفظ الخادم لكل إجابة: وقت فتح السؤال، وقت الاستلام، اختيار السفير، الصحة، زمن الاستجابة المعتمد، درجة السرعة، والدرجة النهائية.

## توزيع حوض ثابت

1. استبعد من لم يكمل الحد الأدنى أو درجته صفر.
2. احسب `exact = pool × participant_score / total_eligible_score`.
3. امنح الجزء الصحيح لكل مشارك.
4. رتب البواقي الكسرية تنازليًا؛ عند التعادل استخدم المركز ثم معرفًا ثابتًا.
5. وزع النقاط المتبقية واحدة واحدة.
6. تحقق داخل transaction أن مجموع قيود ledger يساوي الحوض تمامًا.

هذه الآلية تعمل بالطريقة نفسها مع 10 أو 100 أو آلاف المشاركين.

## التزامن والإنصاف

- يرسل الخادم نبضات وقت، ويقيس التطبيق فرق الساعة وRTT قبل البداية.
- يحتفظ الخادم بهامش شبكة معلن وصغير، ولا يغير ترتيب إجابتين بعد نشر النتيجة.
- عند انقطاع قصير يعيد التطبيق الاتصال بالتذكرة نفسها ويطلب آخر `sequence`.
- لا تُقبل إجابة بعد الإغلاق، ولا إجابتان للسؤال نفسه.
- عند إلغاء سؤال، يزال من مجموع الجميع قبل حساب الحوض.

## الحماية والتدقيق

- JWT قصير العمر خاص بالمسابقة، ومربوط بحساب السفير والجلسة.
- Rate limit على الانضمام والإجابات وإعادة الاتصال.
- كشف النسخ المعدلة، التوقيتات المستحيلة، وتعدد الجلسات دون عقاب آلي غير قابل للمراجعة.
- سجل تدقيق للمشرف، اعتماد السؤال، تغيير الحالة، احتساب الدرجة، واستلام المكافأة.
- الإجابات الصحيحة تحفظ في الخادم ولا تُضمّن في حزمة التطبيق الإنتاجية.

## لوحة الإدارة المطلوبة

- جدولة المسابقة والحوض والمدة وشروط الأهلية.
- إنشاء بنك الأسئلة ومسار المراجعة والاعتماد.
- تشغيل/إيقاف/إلغاء سؤال ومراقبة الاتصال.
- معاينة توزيع الحوض قبل النشر وتصدير سجل التدقيق.
- ضبط مكافآت جولة الأثر وحدودها دون تحديث التطبيق.
